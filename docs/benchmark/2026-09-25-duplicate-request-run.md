# 2026-09-25 동일 요청 검증 실행 기록

같은 `(applicant_id, slot_id)` 예약 요청을 동시에 보낸 [25회 원시 결과](duplicate-runs.csv)의 실행 조건을 기록한다.
결과표와 해석은 [방어 전략 벤치마크](../STEP2-DEFENSE-BENCHMARK.md#3-2-동일-요청-25회--db-안전성과-http-의미)에 둔다.
서로 다른 지원자의 정원 경쟁과는 다른 실험이므로 성능 수치를 합치지 않는다.

## 실험 조건과 판정

매 실행에서 정원 200 슬롯과 지원자 한 명을 새로 만든 뒤 같은 요청을 200건 동시에 보냈다.
다섯 전략을 각각 5회 실행하고, 라운드마다 시작 전략을 한 칸씩 옮겨 각 전략이 모든 실행 위치에 한 번씩 오도록 했다.

**정원을 1이 아니라 200으로 둔 이유:** 정원 1이면 첫 예약 뒤 나머지 요청이 만석으로 거절되어
중복 INSERT까지 도달하지 않을 수 있다. 충분한 정원을 두어 UNIQUE 충돌과 실패 트랜잭션의
좌석 차감 롤백을 확인했다.

통과하려면 매 실행에서 아래 조건을 모두 만족해야 한다. 중복 행이 0개라는 사실만으로는 예약 자체가 실패한 경우를 구분할 수 없다.

- HTTP 결과 합계 200건, 201은 1건, 기타 상태·무응답은 0건
- 독립적으로 집계한 Gatling OK/KO와 HTTP 상태 집계가 일치
- 확정 예약과 해당 지원자·슬롯 조합의 예약이 각각 1건
- 잔여석 199개, 좌석 소모 1개, 중복 행 0개
- `/unique`는 나머지 199건을 409로 응답하고 500·503은 0건
